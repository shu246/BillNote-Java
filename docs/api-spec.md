# API仕様書

Python版（FastAPI）の現在の挙動を記述したもの。Java版はこの仕様と同じ動きをすることを目標とする。

## 0. 共通事項

| 項目         | 内容                                                             |
| ------------ | ---------------------------------------------------------------- |
| ベースパス   | `/billnote-api`（本番は API Gateway のステージ `/default` の下） |
| 文字コード   | UTF-8                                                            |
| JSONのキー名 | スネークケース（例: `invoice_id`）                               |
| CORS         | すべてのオリジン・メソッド・ヘッダーを許可                       |
| 認証         | なし（API Gateway 側で IP 制限）                                 |

### エラーレスポンスの形式

アプリが返すエラーは次の形式。フロントエンドは `detail` を画面に表示する。

```json
{ "detail": "エラーメッセージ" }
```

入力チェック（必須項目の不足、型の不一致、範囲外の値）に失敗した場合は、FastAPI が自動で **422** を返す。このときの `detail` は文字列ではなく配列になる。

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["query", "year"],
      "msg": "Field required",
      "input": null
    }
  ]
}
```

## 1. データ項目（請求書）

検索結果やアップロード結果で返る請求書1件分の項目。DynamoDB の `Invoices` テーブルの1レコードに対応する。

| 項目          | 型             | 説明                                                                            |
| ------------- | -------------- | ------------------------------------------------------------------------------- |
| invoice_id    | string         | 請求書ID（UUID）。登録時に発行                                                  |
| customer_id   | string         | 顧客ID（UUID）。電話番号がない場合は `"0"`                                      |
| customer_name | string         | 顧客名（Excelから抽出し、「様」と空白を除去したもの）                           |
| address       | string \| null | 住所。Excelのセルが空なら `null`                                                |
| phone         | string         | 電話番号。Excelのセルが空なら文字列 `"None"`                                    |
| total_amount  | number（整数） | 合計金額（円）                                                                  |
| s3_path       | string         | 請求書ファイルの保存先（`s3://<バケット名>/invoices/<ファイル名>`）             |
| invoice_month | string         | 請求年月（`YYYY-MM` 形式。例: `"2026-06"`）                                     |
| created_at    | string         | 登録日時（ISO 8601 形式、タイムゾーンなし。例: `"2026-06-15T10:30:00.123456"`） |

---

## 2. POST /upload

請求書Excelをアップロードし、内容を抽出して登録する。1回のリクエストで1ファイル。フォルダー単位の登録は、フロントエンドが1ファイルずつ繰り返し呼び出すことで実現している。

### リクエスト

- Content-Type: `multipart/form-data`

| 項目  | 型       | 必須 | 説明                       |
| ----- | -------- | ---- | -------------------------- |
| file  | ファイル | ○    | 請求書Excel（.xlsx）       |
| year  | integer  | ○    | 請求年（範囲チェックなし） |
| month | integer  | ○    | 請求月（範囲チェックなし） |

### 処理の流れ

1. Excelから顧客名・住所・電話番号・合計金額を抽出する（「8. Excel抽出仕様」を参照）
2. 重複チェックを行う。**顧客名・請求年月・合計金額**の3つがすべて一致する請求書が既にあれば、400エラーを返して処理を終える
3. ファイルを S3 の `invoices/<元のファイル名>` に保存する
4. 顧客IDを決める（「9. 顧客IDの判定ルール」を参照）
5. DynamoDB に請求書レコードを登録する

### レスポンス（成功時）

- ステータス: 200

```json
{
  "status": "success",
  "data": {
    "invoice_id": "3f6c...",
    "customer_id": "a1b2...",
    "customer_name": "山田太郎",
    "address": "東京都...",
    "phone": "090-1234-5678",
    "total_amount": 55000,
    "s3_path": "s3://billnote-storage-exceldata/invoices/山田様.xlsx",
    "invoice_month": "2026-06",
    "created_at": "2026-06-15T10:30:00.123456"
  }
}
```

### エラー

| ステータス | 条件                                                                          | レスポンス例                                                                       |
| ---------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 400        | 重複した請求書がある                                                          | `{"detail": "重複エラー: 山田太郎様の2026-06（55000円）は既に登録されています。"}` |
| 422        | `file`・`year`・`month` のいずれかがない、または `year`・`month` が整数でない | FastAPI の入力チェックエラー                                                       |
| 500        | Excelの読み込み失敗、AWSへのアクセス失敗など                                  | `{"detail": "<例外メッセージ>"}`                                                   |

## 3. GET /search/month

請求年月で請求書を検索する。

### リクエスト

| 項目  | 場所   | 型      | 必須 | 説明             |
| ----- | ------ | ------- | ---- | ---------------- |
| year  | クエリ | integer | ○    | 請求年。2000以上 |
| month | クエリ | integer | ○    | 請求月。1〜12    |

例: `GET /billnote-api/search/month?year=2026&month=6`

`year` と `month` を `YYYY-MM` 形式（月は0埋め2桁）に変換し、`invoice_month` が完全一致する請求書を返す。

### レスポンス（成功時）

- ステータス: 200
- 並び順は指定なし（DynamoDB の返した順）
- 該当なしの場合は `results` が空配列

```json
{
  "results": [
    {
      "invoice_id": "...",
      "customer_id": "...",
      "customer_name": "山田太郎",
      "...": "（1. データ項目と同じ）"
    }
  ]
}
```

### エラー

| ステータス | 条件                                       | レスポンス例                                 |
| ---------- | ------------------------------------------ | -------------------------------------------- |
| 422        | パラメータがない、整数でない、または範囲外 | FastAPI の入力チェックエラー                 |
| 500        | DynamoDB へのアクセス失敗など              | `{"detail": "検索エラー: <例外メッセージ>"}` |

---

## 4. GET /search/customer

顧客名で請求書を検索する（部分一致）。

### リクエスト

| 項目 | 場所   | 型     | 必須 | 説明                                     |
| ---- | ------ | ------ | ---- | ---------------------------------------- |
| name | クエリ | string | ○    | 顧客名。一部だけでもよい（例: 苗字のみ） |

例: `GET /billnote-api/search/customer?name=山田`

`customer_name` に `name` を**含む**請求書を返す。大文字・小文字やスペースの違いは区別される。

### レスポンス（成功時）

- ステータス: 200
- 形式は `/search/month` と同じ（`{"results": [...]}`）

### エラー

| ステータス | 条件                          | レスポンス例                                                                |
| ---------- | ----------------------------- | --------------------------------------------------------------------------- |
| 422        | `name` がない                 | FastAPI の入力チェックエラー                                                |
| 500        | DynamoDB へのアクセス失敗など | `Internal Server Error`（例外処理がないため、JSONではなくプレーンテキスト） |

---

## 5. GET /search/customer_id

顧客IDで請求書を検索する。請求書一覧で顧客IDをクリックしたときに使われる。

### リクエスト

| 項目        | 場所   | 型     | 必須 | 説明               |
| ----------- | ------ | ------ | ---- | ------------------ |
| customer_id | クエリ | string | ○    | 顧客ID（完全一致） |

例: `GET /billnote-api/search/customer_id?customer_id=a1b2c3d4-...`

### レスポンス（成功時）

- ステータス: 200
- 形式は `/search/month` と同じ（`{"results": [...]}`）

### エラー

| ステータス | 条件                          | レスポンス例                                |
| ---------- | ----------------------------- | ------------------------------------------- |
| 422        | `customer_id` がない          | FastAPI の入力チェックエラー                |
| 500        | DynamoDB へのアクセス失敗など | `Internal Server Error`（プレーンテキスト） |

## 6. GET /download

S3 に保存された請求書Excelをダウンロードする。フロントエンドはリンク（`<a href>`）で直接開く。

### リクエスト

| 項目    | 場所   | 型     | 必須 | 説明                                             |
| ------- | ------ | ------ | ---- | ------------------------------------------------ |
| s3_path | クエリ | string | ○    | 請求書の `s3_path` の値（URLエンコードして渡す） |

例: `GET /billnote-api/download?s3_path=s3%3A%2F%2Fbillnote-storage-exceldata%2Finvoices%2F...`

### レスポンス（成功時）

- ステータス: 200
- Content-Type: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- Content-Disposition: `attachment; filename=<URLエンコードしたファイル名>`
- ボディ: Excelファイルのバイナリ

### エラー

| ステータス | 条件                                       | レスポンス例                                         |
| ---------- | ------------------------------------------ | ---------------------------------------------------- |
| 422        | `s3_path` がない                           | FastAPI の入力チェックエラー                         |
| 500        | ファイルが存在しない、パスの形式が不正など | `{"detail": "ダウンロードエラー: <例外メッセージ>"}` |

## 7. POST /update-customer

請求書の住所・電話番号を更新し、顧客IDを判定し直す。

### リクエスト

- Content-Type: `application/json`

| 項目       | 型     | 必須 | 説明                       |
| ---------- | ------ | ---- | -------------------------- |
| invoice_id | string | ○    | 更新する請求書のID         |
| address    | string | ○    | 新しい住所（空文字可）     |
| phone      | string | ○    | 新しい電話番号（空文字可） |

```json
{
  "invoice_id": "3f6c...",
  "address": "東京都...",
  "phone": "090-1234-5678"
}
```

### 処理の流れ

1. `phone` が空文字なら `"None"` に置き換える。それ以外は前後の空白を除去する
2. 新しい電話番号で顧客IDを判定する（「9. 顧客IDの判定ルール」を参照）
3. 対象の請求書の `address`・`phone`・`customer_id` を上書きする

### レスポンス（成功時）

- ステータス: 200

```json
{ "status": "success", "message": "正常に更新されました" }
```

### エラー

| ステータス | 条件                                                | レスポンス例                     |
| ---------- | --------------------------------------------------- | -------------------------------- |
| 422        | 項目が足りない、または文字列でない（`null` を含む） | FastAPI の入力チェックエラー     |
| 500        | DynamoDB へのアクセス失敗など                       | `{"detail": "<例外メッセージ>"}` |

## 8. Excel抽出仕様

アップロードされたExcelの**一番左のシート**から、次のセルを読み取る。数式のセルは計算結果の値を読む。

| 項目          | セル | 加工                                         |
| ------------- | ---- | -------------------------------------------- |
| customer_name | A5   | 「様」を削除し、全角・半角の空白をすべて削除 |
| address       | C42  | なし（空なら `null`）                        |
| phone         | C44  | 前後の空白を除去。空なら文字列 `"None"`      |
| total_amount  | H32  | 空なら `0`。保存時に整数に変換               |

## 9. 顧客IDの判定ルール

アップロード時と住所・電話番号の更新時に、同じルールで顧客IDを決める。

1. 電話番号が `"None"` または空文字なら、顧客IDは `"0"`
2. 同じ電話番号を持つ請求書が既にあれば、その請求書の顧客IDを使う（名寄せ）
3. どちらでもなければ、新しい UUID を発行する

## 10. 既知の課題（Java移行時に扱いを決める）

現在の Python 版の挙動のうち、不具合や注意が必要な点。Java版で同じ挙動にするか直すかは、移植時に個別に決める。

| #   | API                                   | 内容                                                                                                                                          |
| --- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | /upload                               | S3 のキーが元のファイル名だけなので、**同じ名前のファイルをアップロードすると前のファイルが上書きされる**（別の月の請求書でも上書きされる）   |
| 2   | /upload                               | 電話番号のセルが数値型の場合、文字列化の際に先頭の `0` が消える                                                                               |
| 3   | /upload                               | 顧客名のセル（A5）が空だと、重複チェックで例外になり 500 エラーになる                                                                         |
| 4   | /upload                               | `year`・`month` の範囲チェックがない（`/search/month` にはある）                                                                              |
| 5   | /search/customer                      | DynamoDB の scan を1回しか実行しないため、データ量が増えると（約1MB超）一部の結果が返らない。query を使う他の検索も同様にページングしていない |
| 6   | /search/customer, /search/customer_id | 例外処理がなく、エラー時のレスポンスが JSON ではない                                                                                          |
| 7   | /download                             | 任意の `s3_path` を受け付けるため、Lambda の権限で読めるファイルなら何でもダウンロードできる                                                  |
| 8   | /update-customer                      | 存在しない `invoice_id` を指定しても、エラーにならず新しいレコードが作られる（DynamoDB の update_item の仕様）                                |
| 9   | /update-customer                      | 電話番号が空白だけの場合、`"None"` ではなく空文字が保存される（顧客IDは `"0"` になる）                                                        |
| 10  | 共通                                  | データがない電話番号が、null ではなく文字列 `"None"` で保存される                                                                             |
| 11 | 共通 | 電話番号がない請求書は、別人でもすべて顧客ID "0" にまとめられる。顧客ID検索で "0" を指定すると無関係な請求書が混ざって表示される |
