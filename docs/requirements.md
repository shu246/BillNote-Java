# 要件定義書
## 1. 背景・目的
* 実家の畳屋におけるアナログな請求書管理をデジタル化し、業務効率化を図るために開発しました。

## 2. 利用者
* 父（社長）
* 母（従業員）
* 自分（手伝い）

## 3. 機能要件
* 請求書（.xlsx）をアップロードすることで、請求書の登録ができる。
  * 顧客名・請求年月・金額の3つがすべて一致する請求書が既にあれば、登録せずにエラーを返す
  * 年月を指定して、請求書の登録ができる。
  * ファイル単位、フォルダー単位で請求書の登録ができる。
  * アップロードされた請求書から氏名、住所、電話番号、金額を抽出して、抽出した情報と請求書ファイルが保存される。
* 年月を指定して、その月の請求書一覧を表示できる。
* 顧客名を指定して、その顧客の請求書一覧を表示できる。
* 顧客ID、請求年月、氏名、住所、電話番号、金額を一覧で表示することができる。
* 請求書一覧の顧客IDをクリックすることで、その顧客IDに対応した請求書を検索することができる。
* 請求書一覧から住所と電話番号を編集することができる。
* 請求書一覧から請求書のExcelファイルをダウンロードすることができる。
* 電話番号で顧客を判別して顧客IDを発行。
  * 電話番号で顧客を同一人物として扱う（名寄せ）。
  * 電話番号がない場合は顧客 ID を "0" にする。
  * 顧客名・請求年月・金額の3つがすべて一致する請求書が既にあれば、登録せずにエラーを返す
  * 住所・電話番号を編集したときも、新しい電話番号で顧客IDを判定し直す。

## 4. 非機能要件
* 自宅の IP アドレスからしかアクセスできない。
* Lambda で動かすので、サーバーの常時起動は不要。
* 月の AWS 費用は無料枠の範囲内に収める。

## 5. 対象外（スコープ外）
* 金額の集計
* 請求書の削除
* ログイン認証
* 請求書Excelの作成

## 6. Java移行の方針
* UIや機能は変えない。
* フロントエンドは書き換えずにバックエンドをjavaに変更。
